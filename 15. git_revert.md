# `git revert <commit>`

A diferencia de [`git reset`](15.%20git_revert.md). **NO borra commits**.

Lo que hace es:

- Crear un nuevo commit que deshace los cambios de otro commit.

## Ejemplo

Tenemos:


``` Bash

A → B → C → D   (main)

```

Y hacemos:

``` Bash

git revert D

```

Donde

- `E` es un commit nuevo

- `E` revierte lo que hizo D

## 1. Diferencia con `reset`

### 1.1. `reset`

``` Bash

A → B → C → D

```

``` Bash

git reset C

```

Resultado:

``` Bash

A → B → C

```

- ❌ Se borra la historia (D desaparece)

### 1.2. `revert`

``` Bash

git revert D

```

Resultado:

``` Bash

A → B → C → D → E

```

- ✔ Historia intacta

- ✔ Todo es transparente

## 2. ¿Por qué existe revert?

Porque en equipos:

- No debemos reescribir historia compartida

Si ya hicimos `push`:


- ❌ `reset` puede causar conflictos a otros

- ✔ `revert` es seguro

## 3. Qué pasa internamente

Si un commit hizo:

``` Diff

+ console.log("hola")

```

El revert crea otro commit con:

``` Diff

- console.log("hola")

```

- Es literalmente el “opuesto”

## 4. Revert de commits antiguos

También podemos hacer:

``` Bash

git revert B

```

Aunque no sea el último.

Git:

- Aplica el “anti-cambio” de B

- Puede generar conflictos si el código cambió después


## 5. Caso especial: múltiples commits

Podemos hacer:

``` Bash

git revert HEAD~2

```
O varios:

``` Bash

git revert A B C

```

## 6. Resumen

- `reset` → cambia la historia (peligroso en equipo)

- `revert` → respeta la historia (seguro)

## 7. Cuándo usar cada uno

Usar `reset` cuando:

- Estamos trabajando solo

- Aún no hacemos `push`

Usra `revert` cuando:

- Ya hicimos `push`

- Estamos en equipo

- No queremos romper historia
