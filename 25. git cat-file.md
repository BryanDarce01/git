# `git cat-file [opción] <hash>`

Sirve para inspeccionar los objetos internos de Git:

- commits

- trees

- blobs

- tags

``` Bash

git cat-file [opción] <hash>

```

### Ejemplo

``` Bash

git cat-file -p abc123

```

    git        → programa Git
    cat-file   → comando de Git
    -p         → opción de cat-file
    abc123     → objeto que queremos inspeccionar

## 1. `-p`

``` Bash

git cat-file -p <hash>

```

`-p` significa: **pretty-print**

Es decir:

- Muéstrame el contenido del objeto de una manera legible.

Por ejemplo, si `<hash>` corresponde a un commit:

    tree 8a31...
    parent 91bc...
    author Bryan ...
    committer Bryan ...

    Agregar login

Si corresponde a un `tree`:

    100644 blob abc123 index.js
    100644 blob def456 package.json

## 2. `-t`

``` Bash

git cat-file -t <hash>

```

También pertenece a `git cat-file`, `-t` significa type.

Es decir:

- ¿Qué tipo de objeto es este hash?

### Por ejemplo:

``` Bash

git cat-file -t abc123

```

Resultado:

- commit

- tree

- blob

- tag

## 3. `-s`

También es de `git cat-file`.

``` Bash

git cat-file -s <hash>

```

`-s` significa **size**.

- Nos dice el tamaño del objeto en bytes.

### Por ejemplo:

``` Bash

git cat-file -s abc123

```

Resultado:

``` Bash

245

```

- Es decir, el objeto tiene 245 bytes.

## Resumen de comandos extras de `git cat-file`

| Comando                  | Significado       |
| ------------------------ | ----------------- |
| `git cat-file -t <hash>` | Tipo del objeto   |
| `git cat-file -s <hash>` | Tamaño del objeto |
| `git cat-file -p <hash>` | Contenido legible |

# Comandos de la terminal

## 1. `> d`

``` Bash

git cat-file -p <hash> > d

```

`>` **no es una opción de Git**.

Es un operador de **redirección de salida de la terminal**.

La terminal interpreta:

- En lugar de mostrar la salida en pantalla, envíala al archivo `d`.

### Entonces:

- `>` → redirige la salida

- `d` → nombre del archivo donde se guardará

## 2. También existe: `>>`

``` Bash

git cat-file -p <hash> >> d

```

La diferencia:

- `>`   → crea/reemplaza el archivo

- `>>`  → agrega al final del archivo

### Ejemplo:

``` Bash

echo "Hola" > archivo.txt

```

deja:

    Hola

Si después hacemos:

``` Bash

echo "Mundo" > archivo.txt

```

queda:

    Mundo

- Se reemplazó.

Pero:

``` Bash

echo "Hola" > archivo.txt
echo "Mundo" >> archivo.txt

```

queda:

    Hola
    Mundo

## IMPORTATE

### Diferencia entre `echo` y `-p`

#### 1. `echo` es un comando de la terminal/shell.

``` Bash

echo "Hola"

```

Significa:

- Escribe `Hola` en la salida de la terminal.

Resultado:

    Hola

- `echo` no sabe nada de Git.

#### 2. `-p`

`-p` es una opción de `git cat-file`:

``` Bash

git cat-file -p <hash>

```

Significa:

- Git, toma el objeto identificado por este hash y muéstrame su contenido de forma legible.

Aquí `-p` no significa "mostrar en pantalla" en general.

Significa específicamente **pretty-print** dentro de `git cat-file`.

## Origen de `cat`

En Linux/Unix `cat` es el nombre de un comando que viene de **concatenate** → concatenar/unir.

El comando:

``` Bash

cat archivo.txt

```

sirve para **mostrar el contenido de un archivo en la terminal**.

Git tomó la idea de `cat`:

- muéstrame el contenido de algo

y creó:

``` Bash

git cat-file

```

que significa:

- muéstrame información y/o el contenido **de un objeto de Git**.
