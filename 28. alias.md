# Alias

## 1. ¿Qué es un alias en Git?

Un alias es simplemente un apodo para un comando.

Por ejemplo, normalmente escribimos:

    git status

Pero lo podemos cambiar de `status` a `s` desde la terminal:

    git config --global alias.s status

Y entonces:

    git s

Hace exactamente lo mismo que:

    git status

## 2. La estructura es:

    git config --global alias.<alias> <comando>

Por ejemplo:

    git config --global alias.co checkout
    git config --global alias.br branch
    git config --global alias.ci commit

## 3. ¿Dónde se guarda ese alias?

En el archivo:

    .gitconfig

Por ejemplo, después de configurar los alias, podemos ver:

    [alias]
        s = status
        co = checkout
        br = branch
        ci = commit

También podemos modificar los alias desde el `gitconfig`.

## Podemos ver lo que tenemos configurado con:

    git config --global --list

## 4. Parámetros para los alias

Git tiene información que obtiene automáticamente del repositorio en el que estamos trabajando.

Por ejemplo, si estamos dentro de un repositorio y podemos:

    git status

no tenemos que decirle:

    git status mi-repositorio

### Lo mismo pasa con muchos comandos.

Por ejemplo:

    git branch

Git sabe:

- Estoy trabajando con este repositorio y estas son sus ramas.

Esto también aparece mucho con `git push`

Por ejemplo, después de clonar un repositorio podrímos hacer:

    git push -u origin main

Aquí le estamos especificando:

    origin → repositorio remoto

    main → rama

Pero después de hacer esa relación con `-u`, podemos hacer:

    git push

Porque Git ya guardó la información de seguimiento (**upstream**) de esa rama.

    rama local main
            ↓
    rama remota origin/main

Entonces Git sabe nuestros alias:

    .gitconfig
    │
    ├── alias.s = status
    ├── alias.co = checkout
    └── alias.br = branch

Y dentro de cada repositorio Git también conoce cosas como:

    Repositorio actual
        │
        ├── rama actual
        ├── remoto "origin"
        ├── upstream de la rama
        └── configuración del repositorio

Entonces podemos usar comandos cada vez más cortos y no es necesario especificar los parámetros.

- Alias --> Nosotros le damos un nombre corto a un comando.

- Parámetros omitidos --> Git ya puede obtener esa información de la configuración/contexto del repositorio.
