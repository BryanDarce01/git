# `git config`

Es el comando que se utiliza para configurar Git. 

Es decirle a git:

- Estas son mis preferencias y estos son algunos datos que quiero que Git utilice.

### Estructura

    git config [nivel] [configuración] [valor]

## 1. Git tiene diferentes niveles de configuración

**Importante**

Git puede guardar configuraciones en diferentes niveles:

    --system
    --global
    --local

En otras palabras:

    SYSTEM   → afecta a todos los usuarios de la computadora
    GLOBAL   → afecta a tu usuario
    LOCAL    → afecta solamente al repositorio actual

La configuración **local tiene prioridad sobre la global**, y la **global sobre la del sistema**.

## 2. `git config --global`

Ejemplo:

    git config --global user.name "Pepe"

Y:

    git config --global user.email "tu-correo@example.com"

Esto le dice a Git:

- Para mi usuario de esta computadora, utiliza este nombre y este correo en mis commits.

Si hacemos:

    git commit -m "Agregar login"

Git guarda información como:

    Author: Pepe <tu-correo@example.com>

## 3. ¿Por qué usamos `--global`?

Porque normalmente no queremos configurar nuestro nombre y correo una vez por cada repositorio.

Si tenemos:

    proyecto-A
    proyecto-B
    proyecto-C

con:

    git config --global user.name "Pepe"

la configuración aplica a todos los repositorios.

## 4. Ver la configuración

Podemos ejecutar:

    git config --list

Y Git muestra las configuraciones que tiene disponibles.

También podemos preguntar por una configuración específica:

    git config user.name

o:

    git config user.email

## 5. `--local`

Ahora pensemos que tenemos una configuración global:

    git config --global user.name "Pepe"

Pero en un repositorio específico queremos utilizar otro nombre.

Entramos al repositorio:

    cd proyecto

y hacemos:

    git config --local user.name "Pepe Developer"

Ahora en ese repositorio utilizamos:

    Pepe Developer

mientras que los demás siguen utilizando:

    Pepe

Por eso:

- global → todos los repositorios

- local  → solamente este repositorio

De hecho, cuando estamos dentro de un repositorio, normalmente podemos simplemente hacer:

    git config user.name "Pepe Developer"

porque Git utiliza el nivel local por defecto cuando ejecutas `git config` dentro de un repositorio.

## 6. `--system`

También existe:

    git config --system

Este nivel afecta la configuración de Git para todo el sistema.

    SYSTEM
    ↓
    GLOBAL
    ↓
    LOCAL

Si una misma configuración aparece en varios niveles, la más específica gana.

## 7. Ver de dónde viene cada configuración

Un comando muy útil:

    git config --list --show-origin

Esto muestra qué configuración tenemos y de qué archivo viene.

    file:C:/Users/Pepe/.gitconfig
    user.name=Pepe
    user.email=...

Es útil cuando no recordamos cuando configuramos algún valor

## 8. `git config --global --list`

Si queremos ver específicamente nuestra configuración global:

    git config --global --list

Salida:

    user.name=Pepe
    user.email=...
    core.editor=code --wait

## Ejemplos

Con `git rebase -i`

Git necesita abrir un editor para algunas operaciones.

Podemos decirle que vamos a usar Visual Studio Code:

    git config --global core.editor "code --wait"

El `--wait` es importante porque le decimos a Git:

- "Espera a que termine de editar en VS Code antes de continuar."

Entonces cuando hagamos:

    git rebase -i HEAD~4

Git puede abrir VS Code para que modifiquemos:

    pick ...
    pick ...
    reword ...
    squash ...

## Resumen

``` bash

# Configurar identidad
git config --global user.name "Nombre"
git config --global user.email "el@email.com"

# Ver configuración
git config --list

# Ver una configuración específica
git config user.name
git config user.email

# Ver configuración global
git config --global --list

# Configurar VS Code como editor
git config --global core.editor "code --wait"

```
