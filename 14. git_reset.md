# 1. `git reset <commit>` (modo default = `--mixed`

Mueve el puntero de la rama (y opcionalmente el working directory).

### Ejemplo

```

HEAD → main → A → B → C → D

```

Si hacemos

```

git reset B

```

Estamos diciendo:

- Quiero que `main` vuelva a apuntar a B

```

HEAD → main → B

```

Pero…

- Los archivos NO se borran

- Los cambios de C y D quedan en el working directory

-Ya no están en commits → están **“unstaged”**

Es como decir:

- Deshaz los commits, pero deja los cambios en mis archivos

# 2. `git reset --hard <commit>`

```

git reset --hard B

```

Resultado:

```

HEAD → main → B

```
Y además:

- ❌ Borra TODO lo que venga después

- ❌ Borra cambios en archivos

- ❌ Borra commits C y D (de la vista actual)

Es como decir:

- Regresa TODO a como estaba en B, sin dejar rastro

## Comparación


| Comando         | Commits     | Archivos     | Staging     |
| --------------- | ----------- | ------------ | ----------- |
| `reset` (mixed) | Se eliminan | Se conservan | Se deshacen |
| `reset --hard`  | Se eliminan | Se borran    | Se borran   |

## Resumen

- `reset` → “quiero rehacer commits”

- `reset --hard` → “quiero borrar todo y empezar desde ese punto”
