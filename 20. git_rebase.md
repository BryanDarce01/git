# `git rebase`

`git rebase` tiene dos usos principales:

1. Como alternativa a `git merge`

2. Como herramienta para limpiar el historial de commits

## 1. Rebase como alternativa a merge

Imaginemos que tenemos esto:

    A---B---C  main
        \
        D---E  feature

- `main` tiene `A → B → C`

- Creamos `feature` desde `B`

- En `feature` hicimos `D → E`

- Mientras tanto, `main` avanzó hasta `C`

Si hacemos:

    git switch feature
    git merge main

Git puede crear un merge commit:

    A---B---C---------M  feature
        \           /
        D---E------

`M` representa el commit de merge.

## ¿Qué hace rebase?

En lugar de crear ese commit de merge, podemos hacer:

    git switch feature
    git rebase main

Git toma los commits `D` y `E`, y los vuelve a aplicar encima de `C`:

    A---B---C---D'---E'  feature

Algo importante:

    D → E

se convierten conceptualmente en:

    D' → E'

### ¿Por qué?

Porque Git está creando nuevos commits basados en `C`.

Por eso el historial queda lineal.

## Diferencia Visual

Con `merge`:

    A---B---C---------M
        \           /
        D---E------

Con `rebase`:

    A---B---C---D'---E'

Por eso muchas veces se dice:

- Merge conserva la historia tal como ocurrió.

- Rebase reorganiza la historia para que parezca lineal.

## 2. Rebase como herramienta de limpieza

Ejemplos que escribimos:

    A---B---C---D---E---F

Pero nuestros commits fueron algo como:

    C = "creo archivo"
    D = "arreglo typo"
    E = "otro arreglo"
    F = "ahora sí funciona"

Nuestra historial funciona, pero está un poco desordenado.

### Con interactive rebase:

    git rebase -i HEAD~4

podemos modificar esos últimos 4 commits.

Git muestra algo parecido a:

    pick C creo archivo
    pick D arreglo typo
    pick E otro arreglo
    pick F ahora sí funciona

Y podemos cambiar cosas como:

    pick C creo archivo
    squash D arreglo typo
    squash E otro arreglo
    pick F ahora sí funciona

Así terminamos con algo más limpio:

    A---B---C'---F'

Por ejemplo:

    C' = "implementa funcionalidad X"
    F' = "implementa funcionalidad Y"

En lugar de tener muchos commits pequeños y poco útiles.

## Resumen

### Rebase para integrar una rama

En lugar de:

    git merge main

podemos hacer:

    git rebase main

Y conseguimos un historial lineal.

### Rebase para limpiar commits

Utilizamos:

    git rebase -i

para modificar el historial:

- cambiar el orden de commits

- combinar commits (squash)

- cambiar mensajes

- eliminar commits

- dividir commits, etc.

## Importante 🧨

Rebase reescribe el historial.

Por eso hay que tener cuidado con hacer:

    git rebase

sobre commits que otras personas ya están utilizando.

Por ejemplo, si tenemos:

    A---B---C  origin/main

y otras personas ya tienen esos commits, hacer un rebase que los reescriba puede causar problemas.

Una regla práctica para aprender Git es:

- Rebase nuestros commits locales antes de compartirlos; evita reescribir commits públicos que otros ya están usando.
