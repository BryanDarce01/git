# GitHub Gist 

Es una funcionalidad de GitHub para guardar y compartir fragmentos de código, notas o archivos pequeños de forma rápida.

## ¿Para qué sirve?

Se usa mucho para:

- Compartir ejemplos de código

- Guardar configuraciones

- Tomar notas técnicas

- Mostrar errores o logs

- Compartir scripts rápidos

- Tener código reutilizable

Por ejemplo, en vez de crear un repositorio completo para 20 líneas de código, hacemos un Gist.

## Características

### 1. Cada Gist tiene su propia URL

Podemos compartirlo fácilmente.

Ejemplo:

```

https://gist.github.com/usuario/abc123

```

### 2. Puede tener varios archivos

Un mismo Gist puede incluir:

```

index.js
style.css
README.md

```

### 3. Tiene control de versiones

Igual que Git.

Cada vez que editamos el Gist:

- queda historial

- podemos ver cambios anteriores

- podemos revertir versiones

## Tipos de Gist

### Público

Cualquiera puede encontrarlo y verlo.

### Secreto (secret gist)

No aparece públicamente en el perfil ni en búsquedas.

Pero cualquiera con el link puede verlo.

- Es decir, no es privado realmente.

## Diferencias entre Gist y un repositorio

| Gist                   | Repositorio                     |
| ---------------------- | ------------------------------- |
| Para snippets pequeños | Para proyectos completos        |
| Más simple             | Más estructurado                |
| Rápido de compartir    | Más herramientas                |
| Menos configuración    | Issues, branches, actions, etc. |

## También podemos clonarlos con Git

Un Gist internamente es un repositorio Git.

Podemos hacer:

``` bash

git clone https://gist.github.com/id-del-gist.git

```

Y trabajar normal con Git.

**Un Gist usa Git internamente, por eso**:

- tiene commits

- historial

- clone

- push

- pull

Pero GitHub oculta casi toda la complejidad para hacerlo más simple.
